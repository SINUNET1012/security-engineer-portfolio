퍼플위키: 프로젝트 자료 인덱스

파일/폴더/링크/통계 중심으로 저장소 자산을 탐색하는 문서입니다. 개념 정리 문서는 메인 페이지에서 확인할 수 있습니다.

검색 대기 중

목차

개요 빠른 이해 순서 진행 타임라인 기술 스택 맵 핵심 포인트 폴더/자산 분포 팀원별 자산 대용량 파일 전체 파일 인덱스 외부 참고 링크

1. 개요

이 저장소는 3차 퍼플팀 프로젝트의 실습/회의/매뉴얼/룰셋/개인 작업 자료를 모아둔 통합 작업 공간입니다. 핵심 흐름은 로그 수집(ELK) -> 탐지 룰 작성(Suricata/ModSecurity/Wazuh) -> 자동화(Ansible) -> 검증(Nessus/공격 시나리오)입니다.

2. 빠른 이해 순서

  1. 99_회의록: 일정, 역할, 의사결정 흐름 먼저 파악
  2. 02_학습자료/[3차 흐름 잡기]: 프로젝트 전체 아키텍처/학습 프레임 파악
  3. 03_메뉴얼, 룰셋: 실제 구축 절차와 탐지 룰 기준 확인
  4. 00_개인 폴더: 팀원별 실습 결과물/세부 로그/보조 문서 확인

3. 진행 타임라인

4. 기술 스택 맵

수집/적재

Filebeat, Syslog, Logstash, Elasticsearch

탐지

Suricata(NIDS), ModSecurity(WAF), Wazuh(HIDS)

검증/공격 시나리오

Nessus, 실습 패킷, 모의 공격 로그

자동화/운영

Ansible, 룰 취합, 운영 가이드 문서화

네트워크 실습

OSPF, EIGRP, RIP, IPv6, GRE/IPsec, GNS3

악성코드 분석

CAPE 구성/로그, 샌드박스 운용 트러블슈팅

5. 핵심 포인트 요약

  1. NIDS + HIDS 병행: Suricata만으로 놓칠 수 있는 암호화/호스트 내부 행위는 Wazuh 룰로 보완하는 방향이 명시됨
  2. 로그 기반 자동 대응: 단순 수집이 아니라 Kibana 검증 후 차단 자동화까지 연결하는 운영 루프를 목표로 진행됨
  3. 룰셋 출처: Nessus 스캔 결과와 실제 로그/패킷 증거를 기반으로 ModSecurity/Suricata/Wazuh 룰을 작성하는 구조
  4. Ansible 완성 이후 과제: 팀원 전체가 독자적으로 설명/재구축 가능한 수준으로 지식 이전과 문서 통합 진행
  5. 저장소 용량 특성: 대용량 ZIP/VM 파일 비중이 매우 높아, 공유/백업 정책을 따로 두는 것이 유리함
