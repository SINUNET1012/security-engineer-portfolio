1. 개요

호스트 내부 행위와 시스템 로그를 탐지하는 HIDS 계층입니다.

2. 핵심 개념 심화

  1. Wazuh + Auditd는 호스트 행위/시스템 이벤트를 수집해 이상 징후를 분석하는 HIDS 구성입니다.
  2. 감사 규칙 범위와 알림 수준을 분리 설계해야 소음 없이 의미 있는 경보를 유지할 수 있습니다.
  3. 성능 지표(지연, 실패율, 자원 사용량)와 보안 지표(탐지율, 오탐률)를 함께 관리해야 합니다.
  4. 설정 변경은 스테이징 검증 후 제한된 범위에 점진 적용하는 방식이 안전합니다.
  5. 설정값, 룰, 근거 로그를 1:1 매핑해 재현성과 추적성을 확보해야 합니다.

4. 구현 절차

  1. Wazuh + Auditd 적용 목적과 측정 지표를 먼저 확정합니다.
  2. 입력 데이터 형태와 의존 구성요소를 체크리스트로 정리합니다.
  3. Auditd 수집 범위와 Wazuh 경보 레벨을 분리해 경보 소음을 제어합니다.
  4. 변경 전후 로그를 비교해 품질 지표 변화를 수치로 기록합니다.
  5. 룰/설정 파일과 운영 문서를 동기화하고 변경 이력을 남깁니다.
  6. 소규모 적용 후 범위를 확대하는 단계적 배포 전략을 사용합니다.

7. 운영 체크리스트

  1. Wazuh + Auditd 적용 전 권한, 포트, 의존 서비스 상태를 확인한다.
  2. 입력/출력 로그가 모두 수집되는지 샘플 이벤트로 검증한다.
  3. 정상 트래픽과 공격 트래픽을 분리해 결과를 비교한다.
  4. 오탐/미탐 사례를 별도 기록하고 룰 개선 항목을 추출한다.
  5. 변경 이력(무엇, 왜, 언제, 담당자)을 문서에 남긴다.
  6. Runbook 기준으로 실제 운영 절차를 점검한다.
