2️. Nessus는 정확히 뭐가 다르냐
Nessus의 본질
“포트 기반이 아니라, ‘취약점 가설 기반’”
그래서 Nessus는:
서비스 버전 확인
실제 요청 생성
페이로드 삽입
응답 비교

내부 명령 실행 (credentialed)

네 말대로 **“페이로드까지 집어넣는다”**가 정확함.

“지금부터 Nessus가 어떤 방식으로 스캔을 수행하는지 간단히 설명드리겠습니다.

Nessus는 흔히 포트 스캐너로 오해되는데,
실제로는 **포트를 두드리는 도구가 아니라 ‘취약점 판정 엔진’**에 가깝습니다.

스캔 흐름은 크게 다섯 단계로 나뉩니다.”

① 호스트 식별 단계

“먼저 Nessus는 대상 서버가 실제로 살아 있는지부터 확인합니다.
ICMP나 TCP 기반으로 응답 여부를 확인하는 단계이고,
이 단계에서는 아직 취약점 판단은 이루어지지 않습니다.
말 그대로 ‘이 서버가 존재하는가’를 확인하는 단계입니다.”

② 포트 및 서비스 식별 단계

“그 다음으로 열린 포트와 서비스 정보를 확인합니다.
이 단계는 Nmap과 비슷해 보일 수 있지만,
Nessus 입장에서는 이 정보가 목적이 아니라 수단입니다.

여기서 중요한 건
‘어떤 포트가 열려 있느냐’가 아니라
‘이 포트 뒤에 어떤 서비스가 동작 중이냐’입니다.”

③ 서비스·버전 지문화 단계 (핵심)

“이 단계가 Nessus의 핵심입니다.
Nessus는 단순히 배너만 읽는 게 아니라,
여러 요청을 보내서 서비스의 동작 특성과 정확한 버전을 추정합니다.

예를 들어 Apache인지, Nginx인지
OpenSSL의 정확한 빌드 버전이 무엇인지
이런 정보를 기반으로
‘적용 가능한 취약점 시나리오’를 선별합니다.”

④ 취약점 플러그인 실행 단계

“그 다음이 실제 취약점 검사 단계입니다.
Nessus는 미리 정의된 취약점 플러그인을 실행하는데,
이 플러그인은
‘이 환경이라면 이런 취약점이 존재할 수 있다’는
가설 기반의 검증 코드라고 보시면 됩니다.

이 과정에서
HTTP 요청을 보내거나
파라미터에 페이로드를 삽입하거나
경우에 따라서는 쉘 연결을 시도하기도 합니다.

그래서 XSS 테스트나
Bind Shell, 백도어 관련 트래픽이
네트워크 상에서 실제로 관찰됩니다.”

⑤ 결과 상관분석 및 심각도 산정

“마지막으로 Nessus는
단일 결과만 보고 취약하다고 판단하지 않고,
여러 검증 결과를 종합해서
Critical, High, Medium 같은 심각도로 분류합니다.

이때 사용되는 기준이
CVSS 점수와
실제 악용 가능성입니다.”


“자, 지금 보시는 화면은 Nessus 스캔 결과를 취약점 심각도 기준으로 정리한 요약 화면입니다.

왼쪽부터 보시면 Critical, High, Medium처럼 취약점 레벨이 나뉘어 있는데,
이 레벨은 단순히 ‘위험해 보인다’가 아니라
실제로 공격자가 원격에서 악용 가능한지, 시스템 장악까지 이어질 수 있는지를 기준으로 분류됩니다.

예를 들어 Critical 항목들을 보시면
Apache 관련 취약점, Bind Shell 백도어 가능성,
SSL 취약점처럼 원격 코드 실행이나 쉘 획득으로 이어질 수 있는 항목들이 포함돼 있습니다.

이 화면에서 중요한 점은,
이게 단순한 설정 경고가 아니라
Nessus가 실제 요청을 보내서 취약점이 ‘존재할 가능성이 높다’고 판단한 결과라는 겁니다.

그래서 저희 레드팀에서는
이 중에서도 Critical / High 레벨을 우선순위로 삼아서,
실제 네트워크 상에서 어떤 패킷이 오고 갔는지
그리고 이 트래픽이 보안 장비나 로그에서 어떻게 보이는지를
네트워크팀·서버팀과 함께 분석하려고 합니다.”
저희 레드팀에서 Nessus 기준으로 Critical / High 취약점 리스트를 정리할 예정입니다.
해당 취약점과 시간대가 일치하는 pcap 트래픽을 기준으로,
아래 항목 위주로 분석 부탁드립니다.

스캔 단계 트래픽
포트 스캔 / 서비스 탐지
비정상적인 URL / 페이로드 요청
취약점 검증 단계 트래픽
실제 페이로드 삽입 여부 (XSS, bind shell, RPC, SMB 등)

요청 → 응답 흐름

네트워크 관점 요약
통신 경로 (Source / Destination / Gateway)
사용된 프로토콜과 포트
IDS/방화벽에서 탐지 가능한 포인트

분석 결과는 퍼플팀 공유용으로,
“공격자가 아닌 네트워크 관점에서 본 트래픽 흐름” 위주로 정리 부탁드립니다.
