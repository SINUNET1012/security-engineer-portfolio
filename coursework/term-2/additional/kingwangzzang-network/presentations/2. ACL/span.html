트래픽 미러링이 뭐에요? 🤔

개념 잡기

  • 네트워크 장비(스위치/라우터)를 지나가는 데이터를 복사해서 다른 곳으로 보내는 기술이에요.
  • 흔히 '포트 미러링(Port Mirroring)'이라고도 불러요.
  • 핵심 포인트: 원래 데이터는 그대로 두고, '복사본'만 쓱- 분석 장비로 보내는거죠!

왜 할까요?

  • 모니터링: 네트워크가 느려지거나 끊기지 않게 감시해요.
  • 장애 해결: "왜 안되지?" 싶을 때 패킷을 잡아서 뜯어봐요 (Wireshark).
  • 보안: 나쁜 해커가 침입했는지 감시해요 (IDS/IPS).
  • 기록: 누가 무엇을 했는지 기록으로 남겨둬요.

주요 미러링 삼총사 🕵️‍♀️

1. SPAN

Switched Port Analyzer

동네 친구 (Local). 같은 스위치 안에서 트래픽을 복사해서 옆 포트로 넘겨줘요.

2. RSPAN

Remote SPAN

옆 동네 친구 (L2 Remote). 스위치가 서로 다를 때 사용해요. 트렁크(Trunk)를 타고 이동해요!

3. ERSPAN

Encapsulated Remote SPAN

해외 친구 (L3 Remote). IP 네트워크를 타고 멀~리 있는 곳까지 캡슐에 싸서 보내줘요.

자세히 보기: SPAN (Local)

이론 뽀개기

  • 가장 기본적이고 쉬운 방법이에요.
  • 동작: Layer 2 (같은 스위치 안에서만).
  • Source: 감시하고 싶은 포트나 VLAN. (들어오는거? 나가는거? 둘다? 선택 가능!)
  • Destination: 분석 장비(Sniffer)가 연결된 포트.
  • 주의: 목적지 포트는 감시용으로만 쓰여서 일반 인터넷은 안돼요 🙅‍♀️

[실습 1] GNS3로 SPAN 해보기! 🛠️

실습 시나리오

준비물: L2 스위치 1대 (SW1), PC 2대, Sniffer

PC1 (Source) -> SW1 (Gi0/1) PC2 (Target) -> SW1 (Gi0/2) Sniffer -> SW1 (Gi0/3)

목표: PC1이랑 PC2가 대화하는 내용을 몰래(?) 복사해서 Gi0/3에 있는 Sniffer에게 보내자!

[실습 1] 명령어 입력하기 (Cisco IOS)

설정 순서

  1. 혹시 모를 기존 설정 지우기
  2. 누구를 감시할까? (Source 설정)
  3. 어디로 보낼까? (Destination 설정)
  4. 잘 됐나 확인하기 (Ping & Wireshark)

⚠️ 목적지 포트는 설정하면 인터넷이 끊기니 놀라지 마세요!

Switch-Terminal
SW1(config)# ! 1. 기존꺼 지우기 SW1(config)# no monitor session 1 SW1(config)# ! 2. 소스 설정 (Gi0/1 양방향 감시) SW1(config)# monitor session 1 source interface Gi0/1 both SW1(config)# ! 3. 목적지 설정 (Sniffer 쪽) SW1(config)# monitor session 1 destination interface Gi0/3 SW1(config)# ! 4. 잘 들어갔나 확인 SW1# show monitor session 1 Session 1 --------- Type : Local Session Source Ports : Both : Gi0/1 Destination Ports : Gi0/3

자세히 보기: RSPAN

Remote SPAN (멀리 있는 친구)

스위치가 서로 떨어져 있을 때 사용하는 L2 미러링 기술이에요.

  • 핵심 준비물: 스위치 사이를 연결하는 트렁크(Trunk) 선.
  • RSPAN VLAN: 미러링 데이터 전용 택배 트럭 🚚 (일반 데이터는 못 타요).
  • 구성요소: 보내는 애(Source), 중간 전달자(Intermediate), 받는 애(Destination).

[실습 2] GNS3로 RSPAN 해보기! 🔧

토폴로지 및 시나리오

장비: 스위치 2대 (SW1이 보내고, SW2가 받고), PC, Sniffer

PC1 (Source) -> SW1 (Gi0/1) SW1 (Gi0/0) <-> SW2 (Gi0/0) [트렁크 연결!] Sniffer -> SW2 (Gi0/2)

미션: SW1의 데이터를 복사해서, VLAN 999번 트럭에 태워 SW2로 보낸 뒤 Sniffer에게 전달하라!

[실습 2] RSPAN - VLAN & Source 설정

1. RSPAN VLAN 만들기 (모든 스위치에!)

일반 VLAN이 아니라 remote-span이라고 꼭 알려줘야 해요.

SW(config)# vlan 999 SW(config-vlan)# name RSPAN_VLAN SW(config-vlan)# remote-span ! 중요!!

2. 보내는 스위치 (SW1)

목적지를 포트가 아닌 Remote VLAN으로 설정해요.

SW1(config)# ! 소스 포트 지정 SW1(config)# monitor session 1 source interface Gi0/1 both SW1(config)# ! 목적지는 RSPAN VLAN 999번! SW1(config)# monitor session 1 destination remote vlan 999 SW1(config)# ! 트렁크 확인 (VLAN 999 지나가게) SW1(config)# interface Gi0/0 SW1(config-if)# switchport mode trunk SW1(config-if)# switchport trunk allowed vlan add 999

[실습 2] RSPAN - 받는 스위치 설정

3. 받는 스위치 (SW2)

이번에는 소스가 Remote VLAN이 돼요. (트럭에서 짐 내리기)

  • 트렁크 타고 온 VLAN 999 데이터를 꺼내요.
  • 최종적으로 Sniffer가 있는 포트(Gi0/2)로 보내요.

확인하기

Wireshark를 보면 VLAN 태그가 떼어진 깨끗한 원본 패킷이 보여야 성공!

SW2(config)# ! 소스는 RSPAN VLAN 999번 SW2(config)# monitor session 1 source remote vlan 999 SW2(config)# ! 목적지는 실제 포트 SW2(config)# monitor session 1 destination interface Gi0/2 SW2# show monitor session 1 Session 1 --------- Type : Remote Destination Session Source RSPAN VLANs : 999 Destination Ports : Gi0/2

자세히 보기: ERSPAN (캡슐화) 💊

L3 라우팅

IP 주소만 있으면 지구 반대편으로도 보낼 수 있어요! 거리 제약 끝판왕.

GRE 캡슐화

패킷을 GRE라는 캡슐에 넣고, 새 우편주소(IP)를 붙여서 보내요.

단점?

포장이(Header) 추가돼서 데이터가 커지고, 장비가 포장하느라 힘들어해요(CPU 부하).

[개념 실습] ERSPAN 그림으로 이해하기 🎨

개념도

일반 스위치는 잘 지원 안해서, 고성능 라우터(CSR1000v) 같은게 필요해요.

R1(보내는 곳) [10.1.1.1] | (인터넷 구름 ☁️) | R3(받는 곳) [20.2.2.2] -> Sniffer

흐름: R1이 패킷을 캡슐에 싸서 R3 주소(20.2.2.2)로 택배를 보냅니다. R3는 뜯어서 Sniffer에게 주고요.

[개념 실습] ERSPAN 명령어 맛보기 🍭

R1 (Source)
! 보내는 라우터 (R1) R1(config)# monitor session 1 type erspan-source R1(config-mon)# source interface Gi1 R1(config-mon)# destination ip address 20.2.2.2 R1(config-mon)# origin ip address 10.1.1.1 R1(config-mon)# erspan-id 100 R1(config-mon)# no shutdown
R3 (Destination)
! 받는 라우터 (R3) R3(config)# monitor session 1 type erspan-destination R3(config-mon)# destination interface Gi2 R3(config-mon)# source ip address 20.2.2.2 R3(config-mon)# erspan-id 100 R3(config-mon)# no shutdown

핵심: VLAN이 아니라 IP 주소로 통신해요! ✨

한 눈에 정리하기 📝

구분 SPAN (Local) RSPAN (L2) ERSPAN (L3)
어디까지? 스위치 하나 안에서 트렁크로 연결된 옆동네 인터넷 건너 지구 끝까지
배달 방식 직접 전달 전용 VLAN 트럭 이용 GRE 캡슐 포장 택배
필요한 것 그냥 선 연결 트렁크 선, 전용 VLAN IP 통신(Ping), 좋은 장비
힘든 정도 아주 쉬움 (부하 적음) 보통 (트렁크 좀 씀) 힘듦 (CPU 열일함 💦)

L2 vs L3, 느낌 오죠?

L2 세상 (SPAN/RSPAN)

"난 주소(IP) 몰라, 그냥 MAC만 보고 던져!"

[이더넷 헤더] [데이터] -> 스위치: "IP가 뭐임? 난 L2 헤더만 봄"

스위치는 내용물 안 보고, 그냥 정해진 길로 휙 던져요.

L3 세상 (ERSPAN)

"주소(IP) 보고 네비게이션 찍고 가!"

[새 IP] [GRE] [원래 데이터] -> 라우터: "목적지 IP 보고 길 찾아가렴"

중간 라우터들은 이게 미러링인지 모르고 그냥 일반 데이터인 줄 알고 배달해줘요.
